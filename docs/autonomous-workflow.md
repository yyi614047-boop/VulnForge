# 生成、恢复、外部研究与批量任务

> 高级扩展复用同一套 LangGraph Pipeline；主 CLI 只暴露研究、规划和运行等核心入口。

新增入口复用主 LangGraph 的研究、规划、逐步执行、独立验证和清理。
普通 `run` 不生成代码。`author`、`author-environment`、`recover` 使用模型，配置
`OPENAI_API_KEY`、`PLANNER_MODEL` 和可选 `OPENAI_BASE_URL`；不会隐式加载 `.env`。
所有报告名必须尚不存在。

## 1. 生成并修复脚本


知识卡指定脚本槽位及可信成功判据，脚本文件可尚不存在。模型返回 Python 代码，校验后
在知识库副本中保存、执行。首次生成后最多修复 `--max-repairs` 次，每次使用新环境。
保留代码、提示词、哈希、错误和独立验证证据。模型不能修改断言让验证通过。
详细语义见 [脚本工具](script-tools.md)。

## 2. 从资料生成环境


需要知识卡及其 `sources` 中的本地资料，Compose 可以尚不存在。
模型输出 Compose、Dockerfile、配置等文本，仅允许在环境子目录中写入，不修改知识卡、
初始化或复现脚本。引用原句必须存在，服务名、端口和脚本/证据服务必须匹配。
沿用受限 Compose 校验，不支持 privileged、host network、远程 build 等字段。
返回 `validated` 和 `accepted_knowledge` 代表静态校验通过，尚未证明构建成功。
将返回目录传给 `run --knowledge <目录>` 才会真实部署。

## 3. 失败恢复


先执行现有资料包。失败后模型根据错误、日志、断言和引擎状态，选择修复脚本、修复环境、
全新环境重试或停止。环境修复后重新研究和规划；脚本修复子流程使用剩余预算生成、执行与验证后返回。
动作受类型、预算和清理结果约束。清理失败不继续，不执行任意宿主机 shell 或自动提权。

## 4. 联网研究


搜索适配器使用 Bing RSS，但搜索结果只保留白名单主机及其子域名。每个来源必须是 HTTPS；
抓取和每次重定向均重新校验域名，此外受公共 IP、大小、超时和重定向上限约束。没有
`--allowed-domain` 时不开放联网工具。可重复指定 `--source-url` 跳过搜索，但 URL 仍须
命中白名单。保留来源 URL、抓取时间、原文哈希和截断状态。加 `--model` 可生成结构化事实，
来源 ID 与引用原句会校验。
报告标记 `trusted_for_execution=false`，不会自动变成可信漏洞断言。
可把报告作为本地资料加入知识卡 sources；尚未自动核验来源冲突或为任意 CVE 创建可信知识卡。

## 5. 环境问题处理

主 CLI `run` 默认检测端口，不可绑定时在知识副本中改用可用端口，保持容器内端口不变。
报告记录 `port_selection`；`--fixed-port` 禁用自动选择。
作者流程、恢复、对照和队列也启用端口检测。检测到实际绑定之间仍可能被外部进程抢占，
此时明确失败，不修改系统保留端口范围。

镜像拉取的 EOF、连接重置及部分网关/超时错误会按计划预算重试；认证错误或镜像不存在
不会当作瞬时网络故障重试。未实现自动换镜像源或修改系统代理。

## 6. 版本探测与对照

知识卡可增加可信版本探针，命令仅在指定容器内执行：

```yaml
version_probes:
  - id: python_runtime
    service: web
    command: [python, --version]
    expected_pattern: 'Python 3\.11\.11'
```

探针在启动后、初始化前执行；版本或退出码不匹配时阻止复现并清理。
匹配版本字符串不等于自动确认补丁状态。


两份资料的请求、初始化、复现脚本与独立断言必须相同，脚本哈希也须一致。
分别部署并清理，只有原始版本成功、修复版本正常执行但未复现，才返回 `confirmed_difference`。
修复版本崩溃、脚本报错、健康检查失败均不能证明修复有效。
当前真实对照案例为合成服务，不是真实 CVE。

## 7. 批量队列与续跑


当前为最多 100 个任务的顺序队列，每个任务使用独立项目与报告。OS 文件锁阻止同时恢复
同一队列，进程崩溃会释放锁。知识快照哈希变化则拒绝恢复；完成任务不重跑，待执行任务续跑。
队列仍记 running、但执行报告已结束且清理完成时，可自动核对为完成。
执行状态不明时返回 `needs_reconciliation`，不自动重放副作用或清理未知资源。
尚不支持任意步骤级续跑、未知状态自动修复或并行 worker。

## 验证与边界

```powershell
python -m pytest
python -m examples.authoring_smoke
python -m examples.advanced_smoke
python -m examples.recovery_smoke
```

Docker smoke 使用固定模型响应，分别验证失败后修复、生成配置部署、运行时版本、
合成修复对照、队列恢复不重跑和恢复决策执行。它们不替代真实模型和真实 CVE 环境的验证。
生成代码沿用现有 Docker 实验环境，未增加网络隔离。真实漏洞案例验证仍待后续完成。
